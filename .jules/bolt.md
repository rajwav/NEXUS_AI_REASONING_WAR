## 2024-05-24 - Performance Overhead from UI-Focused Generators in Core Solvers
**Learning:** In this codebase, UI-focused step generators (e.g., `find_path_stepper`) were being reused for core algorithm computations (`find_path`) in search algorithms like A* and BFS. While this avoids duplicating the search logic, it creates severe performance overhead because the stepper instantiates large state dictionaries and string messages at every expansion step, allocating huge amounts of memory and CPU cycles that the instant solver immediately discards.
**Action:** When implementing or modifying core algorithm APIs intended for fast, instant resolution, implement direct, optimized logic (e.g., standard `while open_heap:` loop) rather than delegating to telemetry-heavy generators. Keep telemetry generation separated from core computational throughput.
